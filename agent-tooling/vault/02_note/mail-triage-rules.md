# メールの仕分けルール（`/inbox` が使う判断基準）

`/inbox`（[`.claude/skills/inbox/SKILL.md`](../.claude/skills/inbox/SKILL.md)）がメールを仕分けるときの基準。
**本人が提案を直したら、ここに追記して次から同じ判断をする。** 手順そのものはスキル側に書く。

> [!note] これはひな形
> 元の持ち主の差出人ごとの既定と修正の記録は、個人情報なので抜いてある。使いながら育てる。

## 方針

- **段階的に自動化する。** 第1段は「AIが提案 → 本人が Yes/No で承認 → 実行」。ルールが落ち着いた分だけ、後で自動化を検討する。
- **ゴミ箱も提案してよい。** ただし実行は本人の承認後だけ。自動では捨てない。
- **返信は下書きまで。** 送るのは本人の指示と承認を経てから。
- **アーカイブするときは既読にもする。**
- **受信トレイの外も見る。** フィルタ・カテゴリで受信トレイを素通りしたメールに、要対応のものが混ざる。

## 振り分け先

| 提案 | 使う場面 |
| --- | --- |
| アーカイブ | 読めば済む・中身をカレンダー/タスク/ノートに移し終えた・CCで届いただけ |
| ゴミ箱 | 二度と見ない広告・不要になった自動通知・重複 |
| 既読 | 受信トレイの外にある未読で、対応不要なもの |
| 下書き | 返事が要る。下書きを作って本文を見せる |
| タスク | 本人が動く用事は `main`/`big`/`repeat`、AIに任せられる調査は `agents` |
| カレンダー | 日時が決まった予定・締切。既にあれば更新 |
| ノート | 後で再利用する事実（制度・手続き・決定）。追記先のパスを示す |
| 残す | まだ対応中・近日中に見返す |

## 差出人・種類ごとの既定

| 対象 | 既定 | メモ |
| --- | --- | --- |
| 自分がCCに入っているだけの連絡 | アーカイブ | 本人の対応が要る記述があれば別 |
| ニュースレター・マーケット記事 | 既読（またはゴミ箱） | 本人が読む習慣を示したら「残す」に変える |
| GitHub通知 | 既読/アーカイブ | 自分へのメンション・レビュー依頼だけ報告 |
| セキュリティ事故・情報流出のお知らせ | 中身を確認 → 本人に報告 | パスワード変更などの対応が要るか判断材料を添える |
| （使いながら足す） | | |

## 本人の修正から学んだこと

`/inbox` で本人が提案を直したら、日付・対象・直した内容を1行ずつ足す。上の表に反映したら、ここの行は消してよい。
