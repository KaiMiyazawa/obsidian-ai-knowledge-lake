# タスクの並び替え・スターの判断基準

`/prioritize`（[`.claude/skills/prioritize/SKILL.md`](../.claude/skills/prioritize/SKILL.md)）が読む判断基準。手順はスキル側、基準はこのノートに置く。
本人の修正を「本人の修正から学んだこと」に追記して育てる（[`mail-triage-rules.md`](./mail-triage-rules.md) と同じ運用）。

## 並べ方の2つの型

| 型 | 対象 | 何を決めるか | 実例 |
| --- | --- | --- | --- |
| **リスト型** | 1つのリストの最上位タスク | 上から「先にやる・目に入れたい」順。喫緊のものにスター | 2026-10-14 一時リスト新設時 |
| **手順型** | 1つの親タスクのサブタスク | 実行する順。番号（①②…）を振り直し、親の notes に流れを書く | 2026-10-15 家族の還付申告の手続き |

## リスト型の基準（上から順に効く）

1. **依存関係**: Aの結果がないとBが決まらないなら、Aを上に置く（例: 電話の結果で診断書の日付が決まる）。
2. **取り逃がし・取り返しのつかなさ**: 締切を過ぎると権利がなくなる、遅れるほど受け取れる額が減るもの。
3. **締切の近さ**: `due`、notes の締切、カレンダーの予定日。時刻付きの当日タスクは上へ。
4. **金額・影響の大きさ**: 受け取れる・失う額が大きいもの。
5. **手間の小ささ**: 同程度なら、すぐ終わるものを上に（片付けて数を減らす）。

リストごとの軸:

| リスト | 軸 |
| --- | --- |
| `project` | 一時的な用件専用のリストの例。金額・取り逃がしの緊急度・締切の順 |
| `main` | 締切と依存関係が軸。期限なしの買い物・雑用は下へ |
| `big` | 並びより「いま着手すべきものが上の数件に見えているか」。期限のあるものだけ上へ |
| `agents` | 本人のタスクを先に進めるもの（本人タスクの下調べ）を上へ |
| `repeat` | 並び替えの対象にしない（本人に言われたときだけ） |

## スターの基準

- スターは「本人がスマホで開いたときに真っ先に見るもの」。**目安は今日〜3日以内に動かないと損をするもの**。
- 1リストにつき5〜6件まで。増えすぎるとスターの意味がなくなる。
- 親タスクにスターを付けず、いま動くサブタスクだけにスターを付けてもよい（例: 申請手続きなら、いま動く①だけ）。
- 期限を過ぎた・済んだものからはスターを外す提案をする。

## 手順型の基準

- 手間が減る順（例: 先に自動で取れるかを試し、取れなかった分だけ手で集める）。
- 済んだサブタスクは notes の流れに「済（日付）」と書き、完了にする提案をする。
- 番号は実行順に振り直す。旧番号が会話やノートに出ている場合は、報告に「旧③」のように対応を書く。
- 親タスクの notes に「流れと目安の期限」を書き、セッションが消えても親だけ読めば続きが分かるようにする。
