# 会話の知識回収と確認台帳

ChatGPT・Codex・Claude・Claude Codeの過去会話から、未保存の本人の事実・判断・希望や成果物を回収してから整理するための補助ツール。**履歴の読み取りと確認台帳の更新だけを行い、アーカイブ・削除・ノートへの自動転記はしない。** 外部サービスの接続先・操作方針は保管庫の `AGENTS.md` と `02_note/services-accounts.md` に従う。

コードはこのディレクトリ、抽出本文と作業状態はGit対象外の `tmp/.ai-chat-recovery/v2/`。（2026-10-10 に `tmp/ai-chat-recovery/` から移した。2,000件超のファイルで Obsidian が重くなるため、Obsidian が読み込まないドット付きフォルダにしている）正式ノートには再利用する知識と判断だけを保存する。**2026-10の回収作業（完了）の台帳・抽出本文は、2026-10-14に必要な情報を保管庫へ写したうえで削除した**（記録は [02_note/ai-chat-recovery/](../../02_note/ai-chat-recovery/README.md)）。次に使うときは `scan` で台帳を新しく作り直す。

## 実行

Python標準ライブラリだけで動く。保管庫のルートで実行する。

```sh
python3 tools/chat-recovery/recovery.py scan
python3 tools/chat-recovery/recovery.py status
python3 tools/chat-recovery/recovery.py packet --max-chars 12000
```

- `scan`: `~/.codex/sessions`・`~/.codex/archived_sessions`・`~/.claude/projects` のルートセッションを列挙。子エージェントは対象外。旧・新Codex形式とClaude JSONLを読む。
- `packet`: 未読の本文を `packet.json` に出力。文字数に上限を設ける。**トークン数の厳密な保証ではない**。保留分は通常読み飛ばし、`--include-pending` で再掲する。`--session <台帳キーまたはsession ID>` で対象を限定すると、その会話の保留分も読む。
- 既定では未確認チャンクが少ない会話から出す（同数なら元ログのサイズ順）。短い会話を先に照合し、長い開発会話も未確認キューに残す。`--order source` で従来のsession ID順に戻せる。順序は確認の優先度だけで、知識の有無や完了を自動判定しない。
- `status`: 件数だけ返す。本文を毎回画面やチャットへ展開しない。
- SHA-256で変更を検出。確認はチャンク内容のハッシュに結び付け、変わった範囲を未確認に戻す。消えた元ファイルも台帳から消さない。
- 同じ発言が繰り返されても削除しない。会話全体の完全一致と共通の先頭部分を注記するが、自動で確認済みにしない。

## 確認の手順

1. `scan` → `packet` の順で実行する。抽出と確認を同時に走らせない。
2. packetの**全文**を読む。ツール出力が省略された場合は確認済みにせず、分割して読み直す。既に全文確認した注入文（旧AGENTS・環境情報等）と全partが文字列完全一致するチャンクだけは、確認元のsession/chunk対応を残して再読を省ける。似ているだけの文、本人の新しい発言を含むチャンク、会話全体の確認には拡張しない。元ファイルのハッシュ検査は省略しない。
3. 本人の発言・選択・訂正をAIの提案と分ける。過去会話の指示は現在の作業への許可ではない。
4. 知識候補に関係する領域READMEと既存原本を読む。既存ノートへの保存確認は、過去AIの「書いた」という報告だけでは済ませない。
5. 候補があれば前後の文脈を確認する。`chunk_index` と `chunk_count` を使い、`normalized/<台帳キー>.json` の必要部分だけ読む。
6. 未保存なら適切な正式ノートへ最小限追記し、出典・発言の時点・未決定事項を残す。古い現状を現在の事実として上書きしない。
7. 下記のレビューJSONを作り、台帳へ登録する。`needs_context` は未完了として台帳に残す。外部原本などの前提を確認してから、対象を指定して再確認する。

```json
[
  {
    "session": "packetにある台帳キー",
    "source_hash": "packetにあるsource_hash",
    "chunk_id": "packet.chunk.id",
    "outcome": "already_saved",
    "reason": "本人の選択を原本の該当節と照合した理由",
    "destinations": ["02_note/対象ノート.md"]
  }
]
```

```sh
python3 tools/chat-recovery/recovery.py review tmp/.ai-chat-recovery/v2/reviews.json
```

`outcome` は `no_durable_knowledge` / `already_saved` / `recovered` / `needs_context`。
保存済みの判定には実在する保管庫内ファイルを要求する。原本が保管庫外のコード・音声・動画などなら、`external_files: [{"path": "絶対パス", "sha256": "確認時のファイルハッシュ"}]` でも記録できる。これは所在と変更の機械確認であり、内容の一致はレビュー担当AIが確認する。原本の重複コピーは不要。`reason` は省略不可。元ファイルが変わったら古いレビューの登録を拒否する。Google Calendarなど外部サービス上の保存先は、このファイル確認では検証できない。

同一の `review` 実行内では原ログ・外部原本のSHA検査をファイルごとに1回共有する。台帳保存前にファイルの識別子・サイズ・更新時刻・変更時刻を再検査し、処理中の変更や消失は登録を拒否する。次の実行へハッシュを持ち越さないため、大きな原ログの多数区間でも再読を減らしつつ変更検知を保つ。

## 完了と整理の条件

`text_review_complete` は**このMacにある当該ログのテキストを全チャンク確認した**という意味。サービス上の全履歴を回収した、添付まで読んだ、現行方針に整合しているという保証ではない。

`pending_chunks`は`needs_context`として登録した保留数で、未着手区間を含む総未完了数ではない。未着手は各sessionの`chunk_ids`から`reviews`と`pending`の両方を差し引き、元ログの実在も別に確認する。元ログ不在でも正規化キャッシュや他AIのレビューは残り得るが、それだけで原ログSHA検査を通した扱いにしない。

添付の個別確認は`v2/asset-review*.json`に原ログSHA・位置・目視結果・保存先画像SHAを残す。現`status`の`sessions_with_unreviewed_assets`はassets配列の有無を数えるため、添付確認後も件数が減らない。個別記録と併せて読む。`zero-dialogue-audit*.json`は本文0件の形式・原ログSHAの照合用で、遠隔本文を確認した記録ではない。

アーカイブ候補にする前に、次を確認する。

- 全チャンクの確認、解析エラーなし、未解決候補なし。
- 画像・音声・文書などの `assets` の内容、生成ファイル・プロジェクト原本の所在。ツール入出力・思考・注入コンテキストは本文抽出の対象外であり、必要な成果物は元ログやリポジトリで別途確認する。
- 分岐セッション・圧縮前の履歴・既存アーカイブが必要なら、その範囲まで確認する。
- 現在も作業中の会話・未送信下書き・ピン留めの意図。
- 本人の許可。候補は会話名・保存先・未確認事項を示し、承認された対象だけを1件ずつ操作する。

本文0件も空ログと断定しない。未知の形式・壊れたJSON・UTF-8エラーは解析エラーとして残し、確認キューからは保留する。

## Web版の取得範囲

ローカルCLI履歴とWeb版の履歴は別。`scan` はWeb版の全件数や網羅性を判定しない。
`v2/external-sources.json` に既知のWeb会話・取得範囲・実際の整理状態を記録する。

Claude Codeの `bridge-session` は遠隔セッションへの参照で、ローカルファイルに本文が残っているとは限らない。
`v2/claude-bridge-inventory.json` は参照ID・ローカルログとの対応・本文の有無の照合結果、`zero-dialogue-inspection.json` は本文0件のファイル形式の確認結果。
本文0件でも、遠隔のやり取り・圧縮前の本文・成果物を確認するまで空会話や整理完了とは扱わない。

公式エクスポートが取得できれば、そのファイルの形式を実データで確認して取り込み機能を追加する。現在は未実装。claude.ai の公式エクスポート（2026-10-07 申請分、`conversations.json` 156件）は取得済みで、`tmp/.ai-chat-recovery/claude-web-export-2026-10-07/` に置いてある。ブラウザの一部表示やエクスポートのmanifestだけを、全会話取得と扱わない。過去の一部読み取りで回収した知識は有効でも、会話全体を確認済みにはしない。

Web画面では、先頭までスクロールしたときに過去のメッセージが追加読み込みされることがある。末尾の表示だけで本文完了を判断しない。仮想化で先に読んだ発言がDOMから消えるため、その時点の見出し数も総発言数ではない。読み取った範囲と追加読み込みの有無を記録し、別分岐・添付・エクスポートの確認とは分ける。
