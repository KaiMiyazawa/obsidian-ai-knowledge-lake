# prioritize — タスクを優先順位で並べ、Yes/No で承認して動かす

判断基準は [`02_note/task-priority-rules.md`](../../../02_note/task-priority-rules.md)。**最初に必ず読む。**
このファイルは手順だけを持つ。基準を変えるときはルール側を直す。

## 1. 対象を決める

引数: `$ARGUMENTS`

- リスト名（`project` / `main` / `big` / `agents`）なら **リスト型**。
- `all` なら、`project` / `main` / `big` / `agents` の4つを続けて **リスト型** で扱う（`repeat` は含めない）。手順は下の「`all` のとき」。
- それ以外の語なら、`gtasks` の `search` で親タスクを探し **手順型**。候補が複数なら `AskUserQuestion` で選んでもらう。
- 空なら、`AskUserQuestion` で対象リストを聞く（選択肢: project / main / big / agents。親タスクは Other に書いてもらう）。

## 2. 集める（読むだけ。ここでは何も変更しない）

1. `list_task_lists` で ID を取り、`list_with_tree`（未完了のみ）で対象を親子ごと取る。
2. 各タスクの `title` / `due` / `notes` を読む。notes に関係ノートのパスがあり、金額・締切・依存関係が notes だけで分からないものはノートを読む。全部は読まない。
3. 期限が近いもの・予定に紐づくものは、Calendar の `list_events`（今日〜2週間）で日時を確かめる。
4. **スターの現状は API で読めない。** 分からないまま「付ける／（ほかは）外す」と提案してよい。実行時に `gtasks-ui` の JS で全行のスター状態を一括で読み、差分だけ操作する。
5. 済んでいそうなもの（notes やノートに結果がある）、別のリストに属すべきもの（特定の用件のタスクが `main` にある等）を拾っておく。

## 3. 提案する（Yes/No の選択肢で聞く）

まずチャットに新しい並びの表を出す（`順 | ★ | タスク | 期限 | 理由`。理由は1行。手順型は旧番号も書く）。
そのうえで `AskUserQuestion` で聞く。表を出しただけで返事を待たない。

| 問い | 内容 | `Yes` で実行すること |
| --- | --- | --- |
| **並び** | 「この順に並べ替える」。`preview` に新しい並び（番号・タイトル短縮・★）を入れる | `move` で並べ替え。手順型は番号付きタイトルの更新と親 notes の流れの書き直しも |
| **スター** | 付ける／外す対象を列挙 | `gtasks-ui` スキルでスターを操作 |
| **完了・移動**（あるときだけ） | 済んでいそうなもの・別リストへ移すもの。1件ずつ（4件を超えるなら束ねる） | `update`（`status: completed`）/ `move`（`destinationTasklist`） |

- 選択肢は **`Yes`** / **`No`**。直したいときは本人が「Other」に書く（例: 「3と5を入れ替え」「スターは1と2だけ」）。
- 「Other」での指示は、その内容で並びを作り直して実行する。大きく変わったときだけ、新しい並びで1回聞き直す。
- 全部の回答が揃うまで実行しない。

### `all` のとき

1. 手順2で4リストを全部読む（`list_with_tree` は4回まとめて呼ぶ）。
2. **リストをまたぐ移動を先に聞く。** 別のリストに属すべきもの（特定の用件のタスクが `main` にある、AIに頼めば済むものが `main` にある等）と、済んでいそうなものを、最初の `AskUserQuestion` で聞く。移動が決まってから各リストの並びを作る。
3. 各リストの表を `project` → `main` → `big` → `agents` の順にチャットへ出す。並びを変える必要がないリストは「変更なし」と1行で書き、問いにしない。
4. `AskUserQuestion` を1回にまとめる: 「並び」をリストごとに1問（最大4問）。スターはその次の1回で、リストごとに1問。
5. 全部の回答が揃ってから、移動 → 完了 → 並べ替え → スターの順に実行する。スターは4リスト分を1回のブラウザ操作でまとめる。

## 4. 実行する

### 並べ替え（`gtasks` の `move`）

- **上から順に1件ずつ動かす。** 1件目は `previous` を付けずに `move`（リストの先頭へ）。2件目以降は直前に動かしたタスクを `previous` に指定する。
- 手順型は全件に `parent`（親の ID）を付ける。1件目は `parent` だけ、2件目以降は `parent` と `previous`。
- 親タスクを動かせばサブタスクも一緒に動く。サブタスクは個別に動かさない。
- 動かしたあと `list_with_tree` で読み直し、並びが提案どおりか確かめる。

### 手順型のタイトルと notes（`update`）

- 番号付きのタイトル（①②…）は新しい順に振り直す。
- 親タスクの notes に「流れと目安の期限」（①〜⑥とそれぞれの状態・期限）を書く。書き方は [`AGENTS.md`](../../../AGENTS.md) のタスク管理。
- **`due` は変えない。** API で `due` を変えると、画面で付けた開始時刻が消える（`gtasks-ui` の注意書き）。期限を直す必要があるときは、別の問いで本人に聞き、変えたら `gtasks-ui` で時刻を付け直す。

### スター（`gtasks-ui` スキル）

- `Skill` で `gtasks-ui` を呼び、対象タスクの UIID（`webViewLink` の末尾）を渡して付け外しする。複数件は1回のブラウザ操作でまとめて行う。

## 5. 報告する

- 新しい並び（★付き）の表と、実行しなかったもの・失敗した操作をそのまま書く。
- 並べ替えの理由が後でも使う判断（「この件はさかのぼりより事後重症を先にする」など）なら、関係ノートに書く。経過ログは書かない。
- **本人が提案を直したら（`No` や「Other」での変更）、[`task-priority-rules.md`](../../../02_note/task-priority-rules.md) の「本人の修正から学んだこと」に1行追記する**（日付・対象・直した内容）。同じ種類の修正が2回続いたら、基準そのものを書き換える提案をする。追記したことは報告の最後に1行で書く。
