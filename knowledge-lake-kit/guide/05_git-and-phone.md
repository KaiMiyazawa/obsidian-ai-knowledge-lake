# Git 管理とスマホ連携

## なぜ Git か

- 履歴が残るので、AI がノートを壊しても戻せる（AI に大胆に任せられるようになる）
- GitHub の private リポジトリに置けば、スマホの AI（GitHub 連携のセッション）からも保管庫を読み書きできる
- 運用コスト0円（Obsidian Sync を使わなくても回る）

**リポジトリは必ず private にする。**

## 基本ルール

```bash
# 1. 作業前・ステージ前に取り込む
git pull --rebase --autostash

# 2. 作業する

# 3. 状態を確認（意図しない deleted がないか）
git status

# 4. 必要なパスだけステージしてコミット
git add <パス>
git commit -m "…"

# 5. もう一度取り込んでから push
git pull --rebase --autostash
git push
```

- **`git add` の前に pull する。** autostash はステージを外すので、add の後に pull すると何もコミットされない。
- **push が拒否されたら、取り込んでからやり直す。`--force` は使わない。** 別の場所で書いたコミットを消す事故になる。
- **`git add -A` の前に `git status` を目視する。** 意図しない削除を巻き込むことがある。

Codex ならフック（`tools/codex-hooks/guard.py`）がこれを自動でやる。AI にコミットさせるときも、このルールを `AGENTS.md` に書いておく。

## スマホから書く経路

| 経路 | 向いていること | 注意 |
| --- | --- | --- |
| スマホの Obsidian（Git 同期プラグイン等） | 日記を書く | 保管庫全体を同期すると重く、競合も起きやすい |
| スマホの AI（GitHub 連携のセッション） | 外出先で「これメモしといて」 | PC 側のローカルが最新とは限らなくなる → PC 側は必ず pull してから作業 |

### 慣れてきたら: 日記だけ別リポジトリにする

日記はスマホから毎日書くので、保管庫本体とは別リポジトリ（Git サブモジュール）にすると、スマホは日記リポジトリだけを同期すればよくなり、軽く、競合しにくい。

```bash
# 日記用の private リポジトリを GitHub に作ってから
git submodule add git@github.com:<you>/obsidian-diary.git 01_diary
```

- スマホの Obsidian は日記リポジトリだけを開く（または同期対象を日記だけにする）。
- 親リポジトリを pull しても日記の最新は入らない。日記を読むときは `01_diary/` の中で別に pull する。
- PC から日記を直すときは、サブモジュール内でコミット → 親でポインタを進める、の二段階。
- 同じ日付のファイルを PC とスマホで同時に編集しない。競合したらスマホ側を優先する。

最初からやる必要はない。日記を書く習慣がついて、同期が重いと感じてからでよい。

## 重いものを入れない

- 開発中のコード（`node_modules`・`.venv` を持つもの）は保管庫の外（`~/Documents/<名前>/`）へ。保管庫には判断と参照だけ。
- 大量の生データは `.data/` などドット付きフォルダへ（Obsidian が読み込まないので重くならない）。Git にも入れたくなければ `.gitignore` へ。
- 動画・大きな PDF 原本は NAS やクラウドドライブへ。ノートには場所と要点だけ。
