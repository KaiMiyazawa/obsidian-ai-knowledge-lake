# なぜこの作り方で便利になるのか

保管庫を約1年、Claude Code と Codex に毎日読ませて運用してきて、効いていると分かったことだけを書く。

## 一言でいうと

**保管庫は「自分のためのメモ帳」ではなく、「AI に渡す自分の取扱説明書兼記憶」として作る。**
AI は会話が終わると全部忘れる。毎回「私は学生で、今こういう状況で…」と説明する代わりに、AI が保管庫を読めば分かる状態にしておく。
すると「来月の引っ越し、何をすればいい？」の一言で、AI が住まいのノート・お金のノート・予定を読んで、自分専用の答えを出してくる。

## 効いている原則

### 1. 入口を1つにする（`AGENTS.md` → `README.md` → `00_self/`）

AI は毎回ルートの `AGENTS.md` を読む。そこから `README.md`、`00_self/now.md` へと辿らせる。
**「どこから読めば全体が分かるか」が決まっているだけで、AI の的外れが激減する。**
指示書は1本だけ。Codex 用・Claude 用と分けると、片方だけ更新されてずれる。

### 2. `now.md` に日付を付ける

一番効くのは「今の自分」のノート。ただし古い「今」は害になる（もう辞めたバイトの前提で提案してくる）。
だから更新日を書き、「3ヶ月更新がなければ鵜呑みにせず確認しろ」と AI に書いておく。

### 3. `values-principles.md` に「AI への含意」を書く

価値観を書くだけでなく、「だから AI にはこう振る舞ってほしい」まで書く（結論から言う、根拠を出す、感情の話は先に聞く、など）。
**これを書いた日から、AI の返答の質が目に見えて変わった。**
「恒常的な性質」と「今だけの心境」を分けて書く。一時期の落ち込みを人生の価値観として扱わせないため。

### 4. 判断は「なぜ」と一緒に残す（意思決定ログ）

結論だけ残すと、AI は前提が変わっても同じ結論を推してくる。
背景・選択肢・決め手・**前提が崩れる条件**を残すと、AI は「その前提はもう崩れていますね」と言えるようになる。
小さな判断（「この MCP は入れない」「このサービスはやめた」）も、理由を1行添えて残す。**次に同じ調査をやり直さずに済む。**

### 5. フォルダごとの README が「ルールブック」

各フォルダの README に「何を集めるか」「何を集めないか」「取り扱い（機微度）」を書く。
AI は新しいノートを置く前にそれを読むので、置き場所が勝手にぶれない。全体の分類表を1つ作るより、現場ごとに書く方が保守しやすい。

### 6. 原本を1つに決める。二重管理しない

同じ事実を2か所に書くと必ずずれ、どちらが正しいか分からなくなる。
- 経歴の原本は `timeline.md`、履歴書（`89_profile/`）はそこからの派生
- 家計簿は書き写さない（原本は家計簿アプリ）。保管庫には「判断の文脈」だけ
- タスクは保管庫に書かない（原本はタスク管理ツール）→ [`02_tasks.md`](./02_tasks.md)

### 7. 「今の正解」は上書き、「なぜ」は追記

手順や現状は古い記述を消して上書きする。日付付きの作業ログを積み重ねると、AI が読むたびに文脈（トークン）を食い、古い情報に引きずられる。
残すのは判断の理由だけ。

### 8. AI が単独で読める文で書く

「例の件」「あの人」と書かない。固有名詞は `glossary.md` に1行足す。
分からないことは推測で埋めずに「未確認」と書く。AI にも同じルールを課す（推測で埋めた事実が一番危ない）。

### 9. リンクは相対パスの Markdown リンク

`[表示名](./note.md)` で書く。wikilink（`[[note]]`）は、`README.md` のような同名ファイルが増えると AI が一意に辿れない。相対パスなら AI も GitHub も Obsidian も迷わない。

### 10. 手段の順序を決めておく

ローカルのファイルと CLI → MCP / API → ブラウザ操作 → 人の手作業、の順。
「AI にはできないので手作業で」と言う前に、ブラウザで届かないか試させる。逆に、MCP で届くものをブラウザでやらせない（文脈を桁違いに使う）。→ [`04_tools-and-mcp.md`](./04_tools-and-mcp.md)

### 11. 安全装置は「指示」と「仕組み」の二重にする

AI は指示を読み飛ばすことがある。Git の force push や一括削除、メール送信のような取り返しのつかない操作は、`AGENTS.md` に書くだけでなく、フック・承認設定で機械的にも止める。→ [`03_ai-permissions.md`](./03_ai-permissions.md)

## やらなくていいこと

- 最初から完璧な分類を作る（使いながら README を直せばよい）
- タグの体系を作り込む（AI はフォルダと README とリンクで十分に辿れる）
- Obsidian のプラグインを大量に入れる（AI が読むのはただの Markdown）
- Obsidian 用の MCP を入れる（ローカルなので AI は直接読める）
