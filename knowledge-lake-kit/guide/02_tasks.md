# タスク管理 — 実行タスクは保管庫に書かない

## 方針

- **実行タスク（「〜する」「〜を確認する」）はタスク管理ツールに置く。** 例では Google Tasks（スマホで見やすく、MCP で AI からも読み書きできる）。
- **保管庫に残すのは判断の記録だけ。** 「やらないと決めたこと」「方針として決まったこと」「なぜそのタスクが必要か」。
- ノートに `- [ ]` を溜めない。終わったチェックボックスが積み上がり、AI が「今どうなっているか」を読み違える。

**「今どうなっているか」の正はタスク管理ツール側。保管庫は「なぜ」の正。**

## リストの分け方（例）

まず「AI に投げれば済むか、自分が動く必要があるか」で分け、自分が動くものだけ粒度で分ける。

| リスト | 入れるもの |
| --- | --- |
| `agents` | **AI に依頼すれば済むタスク。** 調査・下調べ・見積もり・文書作成など |
| `main` | 自分が動く必要がある、短期で片付くタスク |
| `big` | 抽象度が高い・大きい・期限がないタスク。人生単位のもの |
| `repeat` | 繰り返し発生するタスク |

特定の人・プロジェクトのタスクが増えすぎたら、一時的な専用リストを作り、終わったらリストごと消す。

## `agents` リスト — AI への引き継ぎ箱

会話の中で「今はやらないが AI に頼めば済む」と思ったら `agents` に入れておく。
**AI の起動時にこのリストを自動で読ませる**と、新しいセッションの AI が勝手に拾って進められる。

- Codex: `.codex/hooks.json` の `SessionStart` に、タスク MCP の一覧取得ツールを呼ぶ `mcp_tool` フックを足す。
- Claude Code: `.claude/settings.json` の `hooks.SessionStart` に同じものを足す。

```json
{
  "type": "mcp_tool",
  "server": "gtasks",
  "tool": "list_with_tree",
  "input": { "taskListId": "<agents リストの ID>" },
  "timeout": 15,
  "statusMessage": "agents リストを確認中..."
}
```

（サーバー名・ツール名は、使うタスク MCP に合わせる。起動時に MCP の接続が間に合わないことがあるので、注入されなければ AI が自分で取りに行くよう `AGENTS.md` に書いておく。）

判断が要る箇所に来たら、AI はそこで止めて本人に確認する。ログイン・支払い・通院・買い物のような「AI にはできない用事」は `agents` に入れない。

## notes に手順と前提を書く

`agents` のタスクは、会話の文脈を知らない新しい AI が読む。次のどちらかに当てはまるなら notes を空にしない。

- やることが具体的に決まっている → 手順を番号付きで
- 着手する人が前提を調べ直すことになりそう → 会話で分かった前提を

```text
目的: 〜するため（1行）
手順:
1. …
2. …
前提: 関係ノート 02_note/xxx.md / アカウント … / 確定済み: …
止める条件: 〜の判断が要ったら本人に確認
```

notes は使い捨て。後でも使う判断・背景は保管庫のノートに書き、notes からはパスで参照する。

## 「TODO」の解釈

`AGENTS.md` に「本人が『TODO は何ある？』と言ったら、タスク管理ツールのこと」と書いておく。保管庫内の TODO ノートを指したいときは、ファイル名で言う。
